# Тестирование формы записи на мастер-класс по свечеварению

[Открыть приложение на GitHub Pages](https://qahelping.github.io/aqa-candels/)

## Высокоуровневые требования

1. Форма предназначена для записи на офлайн-мастер-класс по свечеварению.
2. Запись доступна любому посетителю без регистрации и входа в аккаунт.
3. Имя и фамилия вводятся в одно обязательное поле.
4. Для связи участник указывает email. Форма проверяет, что поле заполнено и адрес имеет допустимый формат.
5. Участник обязательно выбирает дату из выпадающего списка. Стрелка списка выровнена внутри поля.
6. Занятия проходят в ноябре по вторникам и четвергам в 19:00 по Минску. На старте на 17, 19 и 24 ноября доступно по одному месту, на 26 ноября — пять.
7. В списке отображаются только даты со свободными местами. После успешной записи число свободных мест на выбранную дату уменьшается на одно. Когда мест больше нет, дата исчезает из списка.
8. Участник прикрепляет чек об оплате перед отправкой заявки. Форма не показывает подсказку о форматах файлов, а статус оплаты подтверждает администратор после проверки чека.
9. После успешной отправки форма показывает участнику подтверждение записи на выбранную дату.
10. В полной версии заявки попадают в Google Таблицу на отдельную вкладку для каждой даты. До проверки администратором статус оплаты — «На проверке», после подтверждения — «Оплачено».

В этой версии опубликована демонстрационная форма. Отправка заявки и изменение числа мест имитируются в открытой вкладке. После обновления страницы исходное число мест восстанавливается. Хранение чеков и заявок, проверка оплаты администратором и интеграция с Google Таблицей относятся к следующим этапам.

## Задание

Найдите дефекты в опубликованной форме. Используйте вымышленные контактные данные и тестовый файл.

- Составьте чек-лист из 8–10 проверок с ожидаемыми результатами. Используйте функциональное тестирование с позитивными и негативными сценариями, проверку граничных значений для доступных мест и исследовательское тестирование.
- Добавьте проверки удобства использования и совместимости. Попробуйте заполнить форму с клавиатуры и проверьте её на узком экране или в другом браузере.
- Оформите отдельный баг-репорт на каждый найденный дефект. Укажите название, требование, окружение, предусловия, шаги, фактический и ожидаемый результаты. Приложите скриншот, если он помогает воспроизвести проблему.
- Если ожидаемое поведение нельзя вывести из требований, сформулируйте вопрос к владельцу продукта. Функции следующих этапов исключите из проверки демоверсии.
